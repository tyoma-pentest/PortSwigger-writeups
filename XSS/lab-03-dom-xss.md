# DOM XSS in document.write sink using source location.search

**Сложность:** Apprentice  
**Тема:** XSS  
**Ссылка:** [PortSwigger](https://portswigger.net/web-security/cross-site-scripting/dom-based/lab-document-write-sink)  

## 1. Описание уязвимости

Параметр `search` из URL передаётся в **`document.write`** без обработки.  
Это позволяет внедрить JavaScript-код, который выполнится в браузере жертвы.

---

## 2. Разведка

Зашел на лабораторную, увидел сайт с блогами, который использовался в первых двух лабах, есть параметр `search`, так же под постами людей можно оставлять комментарии.

![Решение](images/lab-01-1.png)

---

## 3. Ход решения

Попробовал внедрить код `<script>alert(1)</script>` через параметр `search`, не получается, оставить комментарий с произвольным кодом тоже не получается - безрезультатно, решил изменить код таким образом: `"><script>alert(1)</script>`, атака успешно совершенна, это сработало потому, что уязвимый код страницы выглядит так `document.write('<img src="/resources/images/tracker.gif?searchTerms=' + searchTerms + '">');`, то есть если мы впишем `">`, а после него вредоносный код, то станица после `">` будет считать, что все нормально.
